TrendGap v5.3

Find what's missing — then build it.

A market-gap generator: enter a topic, see what already exists, see which angles GitHub Search finds nothing for, and get a concrete fix for each missing angle.

This is NOT an official trending feed — GitHub has no official trending API. “Trending now” below is supporting evidence only: repos created in the last 7 days, sorted by stars in GitHub Search, fetched live from your browser with no key. Ideas are SUGGESTIONS. Only the evidence numbers are data. A “gap” means no repo found by this GitHub search (or only one under 5 stars) — never “nothing exists in the world”. Trending also needs execution, timing and distribution: no idea here is guaranteed to trend or be “top in the world”.

How it works: (1) the topic's top repos are fetched (all stages, all-time, in names/descriptions) and shown as existing repos — what already exists, tiered by stars (Established 100+, Emerging 10–99, Early 0–9; only Established counts as truly saturated); (2) 10 missing-cluster probes run — backup, blur, transcript, captions, dual, search, translate, offline, sync, editor — each as “topic + probe” in names/descriptions; (3) every probe with 0 matches, or only a repo under 5 stars, becomes one gap idea with what's missing, the exact probe evidence, a concrete fix, a 72-hour MVP, and what NOT to build. All 10 probe results are shown — non-missing probes are never hidden. If the topic itself matches nothing, no gap analysis is invented.

Plain topic search (secondary)

The gap generator above is the product. This plain search is kept for exploring a topic's repos directly, with the same all-stages search as the gap finder.

Search runs a live GitHub Search for your keywords in repo names and descriptions, all-time (not just the last 7 days — niche topics like Ray-Ban Meta have almost nothing new in 7 days), ranked by tier first (name/topic match before description-only; SDK/plugin building blocks ranked below end-user tools), then words matched, then relevance, then stars. If your exact words match nothing, it tries shorter versions and tells you which words it dropped. If nothing matches at all, the page says so plainly, shows trending repos only as unrelated exploration, and generates no package from them.

What this evidence is — and is not

  • Is: GitHub Search results — trending: repos created in the last 7 days, sorted by stars, fetched live from your browser (no key, cached 1 hour); topic and gap searches: all stages evaluated and merged, all-time, in names/descriptions, ranked by tier, then words matched, then relevance, then stars — or, only if live search fails, the dated snapshot in data/snapshot.json, clearly labelled as a fallback with its date.
  • Is not: an official trending feed, a complete market survey, or proof that a gap exists in the world. A “gap” is only what one GitHub search did not find. Competitors are other repos in the fetched set with the same language or a shared topic, not a global top 3.
  • Angles and gaps are hypotheses based only on listed topics, language, and search totals. A missing topic or a zero probe result is not proof a feature does not exist — topics and descriptions are not feature lists.
  • Names on ideas are suggestions only. Their npm / PyPI / domain availability was not checked here.
  • Rate limits: unauthenticated GitHub Search is limited (about 10 searches/minute per IP in practice). A gap run makes up to ~15 searches (topic stages + 10 probes), so probes are paced at about one per 7 seconds and the run can still hit the limit — if it does, the page stops, says exactly how many probes were actually checked, marks the rest UNCHECKED with GitHub's reset time when available, and offers a "Retry unchecked probes" button. It never invents results. The trending list then falls back to the snapshot — it never invents repos.
  • No trend guarantee: an idea with a real gap still needs execution, timing and distribution to trend. Nothing here promises stars, ranking, or “top in the world”.
